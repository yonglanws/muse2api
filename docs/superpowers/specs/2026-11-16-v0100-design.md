# 0.10.0 设计：第三轮缺陷审计 — API 表面逐字段对齐真实 OpenAI

第三轮 defect-first 审计（前两轮：0.8.0 单账号并发、0.9.0 异常路径 + 参数执行）。
本轮对象是"最后一层皮"：HTTP 错误形状、响应头、Responses API 的有状态与函数调用、
流式多选、采样上限。所有缺陷均以真实 OpenAI API 行为为对照。

## 1. 缺陷清单（E1–E10）

| # | 缺陷 | 现状 | 真实 OpenAI 行为 |
|---|---|---|---|
| E1 | 404/405 响应体不是 OpenAI 信封 | Starlette 默认 `{"detail": "Not Found"}` | `{"error":{"message":"Invalid URL (POST /v1/xxx)","type":"invalid_request_error","param":null,"code":null}}`；405："Not allowed to GET on /v1/chat/completions. (HTTP status code: 405)" |
| E2 | 错误信封缺 `param` 字段 | `to_body()` 只有 message/type/code | OpenAI 所有错误信封都带 `param`（null 或第一个出错参数） |
| E3 | 无 OpenAI 响应头 | 无 | `x-request-id`、`openai-version: 2020-10-01`、`openai-processing-ms` |
| E4 | 流式 `n>1` 直接 400 | `raise InvalidRequest` | 支持：chunk 内 `choices:[{index:i,...}]` 按选流交错输出，最后 usage chunk |
| E5a | Responses `previous_response_id` 被忽略 | 无服务端状态 | 有状态续聊：加载上一条响应的消息链，继续同一会话；未知 id → 404 + `param:"previous_response_id"` |
| E5b | Responses `tools`/`tool_choice` 被静默忽略 | 工具输入项直接报错，但请求级 tools 没人理 | function calling：输出 `function_call` item，流式有 arguments.delta/done 事件 |
| E5c | Responses 流缺 `response.output_text.done` / `response.content_part.done` | 只有 delta 事件 | item.added → part.added → text.delta* → **text.done** → **part.done** → item.done → completed |
| E5d | Responses 对象字段不全 | 缺 instructions/previous_response_id/store/error/incomplete_details/metadata | 全部存在（多为 null）；`store:false` 不落存储 |
| E6 | 未知 model 静默回落默认模型 | `resolve_model` fallback | 404 `model_not_found`，`param:"model"`，message "The model 'x' does not exist or you do not have access to it." |
| E7 | `stream_options` 无 `stream` 时被接受 | 静默忽略 | 400 invalid_request_error |
| E8 | include_usage 的 usage chunk 缺 `system_fingerprint` | 缺 | 所有 chunk 都带 |
| E9 | `input_audio`/`file` part 被静默丢弃 | 客户端以为音频已处理 | 400：模型不支持该模态（**probe 17 推翻**：上游 file_ref 通道接受任意 MIME，Agent 精确读出 txt 中的密语、确认可处理音频 → 0.10.0 实现为**支持附件**而非拒绝，见 docs/PROTOCOL.md 3.3） |
| E10 | `max_tokens`/`max_output_tokens` 完全无效 | 接受但忽略 | 截断输出，`finish_reason:"length"`（Responses：status=incomplete + incomplete_details） |

## 2. 方案

### E1–E3（app 层）
- `app.py` 增加 `@app.exception_handler(StarletteHTTPException)`：按状态码生成 OpenAI 信封
  （404 "Invalid URL (METHOD path)"，405 "Not allowed to METHOD on path. (HTTP status code: 405)"，
  其余透传 detail 作为 message）。
- `errors.py`：`Muse2APIError` 增加 `param: str | None`，`to_body()` 输出 `param`；校验错误信封
  从第一个 pydantic error 的 loc 生成 param（如 `messages.0.content` → `messages[0].content`）。
- 新增小 ASGI 中间件 `OpenAIHeadersMiddleware`：`http.response.start` 时补
  `x-request-id`（uuid4）、`openai-version: 2020-10-01`、`openai-processing-ms`（响应头发出时刻的耗时）。

### E4：流式多选
- 纯文本计划：n 条临时线程并发（`replace(req, conversation_hint=None)`），pump 任务把
  `(index, delta)` 推入 asyncio.Queue，合并器按到达序发 `{"index": i}` chunk；每选流独立应用
  stop 截断，独立 finish chunk；全部结束后 usage chunk + [DONE]。请求前先对每条流
  gather 首个 delta，失败仍是 HTTP 错误。
- buffered 计划（tools/json）：n 条并发非流式补全（复用 `_retry_nonstream`），再按
  buffered_events 的重放方式逐选流回放 chunk。

### E5：Responses API 补齐
- 新服务 `services/response_store.py`（JSON 文件 `data/responses.json`，TTL `MUSE2API_RESPONSE_TTL`
  默认 7 天，上限 1000 条，load/save 时清理）：存 `{id, messages(已转 chat 消息), model, hint, created}`。
- `previous_response_id`：加载存量消息 + 追加本次 input → 走 chat 的 `_build_plan` /
  `_chat_request`（提取 chat 路由的请求构造为模块级函数复用）；conversation_hint 用存储值，
  同链续线程。未知 id → 404 信封 + `param:"previous_response_id"`。`store:false` 不写存储。
- 函数调用：`tools`/`tool_choice` 映射进 `_build_plan`；`function_call`/`function_call_output`
  输入项转成 chat 的 assistant tool_calls / role:tool 消息；产出解析为
  `{"type":"function_call","id":"fc_..","call_id":"call_..","name","arguments"}` 输出 item；
  流式按 OpenAI 事件序（output_item.added → function_call_arguments.delta/done →
  output_item.done → completed）。
- 流事件补 `response.output_text.done` + `response.content_part.done`；
  响应对象补 `instructions/previous_response_id/store/error/incomplete_details/metadata/temperature/top_p`；
  `max_output_tokens` 截断 → status=incomplete + `incomplete_details.reason="max_output_tokens"`
  + `response.incomplete` 事件；`text.format` → chat 的 response_format。

### E6–E10
- `resolve_model`：未知 → `NotFound("The model '<name>' does not exist or you do not have
  access to it.", param="model", code="model_not_found")`；aliases 增补
  `gpt-4/gpt-4-turbo/gpt-3.5-turbo/o3-mini/o4-mini/gpt-4.1-mini/gpt-4.1-nano/o1/dall-e-2`。
- `stream_options` 存在而 `stream` 非 true → InvalidRequest（chat 路由入口）。
- include_usage chunk 补 `system_fingerprint`。
- `_content_to_text`：`input_audio`/`file`/`input_file` part → InvalidRequest（param 标到消息）。
- `max_tokens`（chat）：cap ≈ limit*4 字符，流式在 stop 机制同位截断 + finish_reason="length"，
  非流式同规则；与 stop 并存取先到者。
